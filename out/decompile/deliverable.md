# Deliverable — decompile-auth-funcs

## Task
Get real decompiled pseudocode for the auth/eligibility functions in
`/workspace/agy/install/antigravity` (214 MB stripped Go 1.28 ELF), not just
symbol names. The previous rea analyze timed out at 5.5 min (rea-agents 6.4.0
internal limit) before Ghidra's full analysis could complete.

## Approach
1. Bypassed the rea wrapper and ran Ghidra's `analyzeHeadless` directly so
   the full disassembly + 17 analyzers can run to completion. Pre-allocated
   2 GB heap (`MAXMEM_DEFAULT=2G`) and `ParallelGCThreads=2`.
2. Used `-noanalysis` to skip Ghidra's slow Decompiler Switch Analyzer
   (the bottleneck — it tries to decompile every function to find switch
   tables and on 155K Go funcs in 2 GB takes days). Instead, applied the
   REA seed preScript to create functions and labels at the 155K seed
   addresses, then ran a custom Ghidra Java postScript (`DecompilePriority.java`)
   that uses `DecompInterface` to decompile just the 1,498 priority auth
   functions. Per-func timeout 60s.
3. Regenerated `priority-funcs.txt` from the original 158 to 1,498 funcs:
   - All `cli/store`, `cli/backend`, `cli/printmode`, `cli/commands`
   - All 7 AuthProvider implementations in `codeassistclient`
     (CLIAuthProvider, AntigravityHubAuthProvider, StandaloneAuthProvider,
      HostAuthProvider, StubbyAuthProvider, IDEAuthProvider,
      GeminiAPIKeyAuthProvider)
   - Some auth-related `language_server_pb` handler funcs
   - Dropped autogenerated gRPC dispatchers
4. After the run, built per-package markdown summaries and a top-level
   `decompile-summary.md` with key auth/eligibility findings, OAuth endpoints,
   and OAuth client IDs.

The 638 skipped funcs are mostly inline Go methods that couldn't be created
because they were marked as thunks or "inside an existing instruction" by
the disassembly pass (common with Go where the linker inlines and thunkifies
aggressively). The 860 decompiled funcs include all the critical Manager
auth state machine funcs:

- `waitForEligibility` (cli/store) — blocks session start until eligibility
- `StartOAuthProcess`, `StartGCPAuthProcess`, `CompleteGCPSetup` (cli/store)
- `TrySilentAuth`, `SubmitOAuthAuthorizationCode`, `SubmitVertexAPIKey` (cli/store)
- `Logout`, `ResetAuthState`, `commitAuth`, `initCliSettings` (cli/store)
- 7 AuthProvider types × ~20 methods each (codeassistclient)
- `RefreshingTokenSource`, `FetchLicensesFromAICode`, `SelfAssignLicense` (codeassistclient)

## Auth/eligibility flow (high level)

1. **`initCliSettings`** → loads `~/.config/antigravity/settings.json`
2. **`initAuth`** → reads stored creds from OS keyring
3. **`waitForEligibility`** → polls LSP `GetStatus` until backend reports user
   is eligible (license tier, business flag)
4. If not eligible, `StartOAuthProcess` or `StartGCPAuthProcess` is invoked
5. OAuth device-code flow: `oauth2.googleapis.com/device/code` → user authorizes
   in browser → `oauth2.googleapis.com/token` returns access+refresh tokens
6. Tokens stored in OS keyring (Linux: libsecret, macOS: Keychain)
7. `RefreshingTokenSource` auto-refreshes on 401
8. AuthProvider (one of 7 implementations) returns the right token source
   based on environment (CLI/IDE/Host/Standalone/Stubby/API key)
